# 执行记录的完整传输

执行器的 `messages.create/patch` 不再按 800 KB 拒绝整条记录，也不截取工具参数、结果或差异。正文及原有消息字段完整保存。

小消息直接写入。超过 256 KiB 的 UTF-8 JSON 通过 `executor-transcripts` 分块传输，每块原始数据最多 256 KiB，使用 Base64 封装。因此每个 Socket.IO 包仍低于 1 MB 的网络包保护值，整条消息没有额外的应用层字节上限。这个分块大小不改变消息内容，也不走带 10 MB JSON 限额的整包 HTTP 备用通道。

服务端每次验证执行器令牌和租户、用户、会话、任务归属。分块暂存在 `DISCO_DATA_HOME/transcript-transfers` 下按作用域和传输 ID 哈希隔离的目录中，不保存令牌。只有字节数、SHA-256、UTF-8 和 JSON 校验全部通过后，才通过原有消息服务及其权限、字段验证和实时通知链路写入一条消息。

收到确认后才发送下一块或继续执行。丢失确认时用同一传输 ID 和偏移重试，已有字节必须一致；提交成功保留轻量回执，重复提交不再重复创建或覆盖消息。完成后删除临时正文，失败时尽力撤销未完成的传输。服务启动及每小时清理超过 24 小时无活动的临时数据和回执。暂存目录需随对应 daemon 使用；正在分块的请求应路由到同一节点。

分块解决单包传输限制，实际可处理内容仍取决于可用磁盘、内存及数据库本身的能力。历史记录中已经截取的展示内容不会由此自动补回。
