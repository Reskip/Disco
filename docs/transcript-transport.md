# 执行记录的传输大小

执行器写入消息时，完整 JSON 请求保持在 800 KB 的传输预算内，给 Socket.IO 协议封装留出空间。预算包含 `content`、预览、工具参数副本和消息元数据，不能只计算工具返回值。

Codex 的工具调用参数以 `content` 中的 `tool_use` 为准。大消息先移除 `tool_uses` 中完全相同的兼容副本；用于子任务分组的 `Task` 引用保留。若单份参数仍然过大，聊天记录显示带说明的参数预览；过大的工具结果保留截取标记，必要时省略差异预览。小消息保持原样。

这些处理只作用于写入 Disco 的展示副本，实际执行的参数和 Codex 原始记录保持完整。用户提示和助手正文不会被这条工具记录规则静默截断，最终传输大小仍由统一校验负责。
